# 报告发送、历史追踪与批量补发

## 使用

报告领取记录提供“发送报告”“再次发送”“发送记录”。确认窗口展示收件邮箱、发件邮箱、报告名称/版本和正文预览；必须勾选核对确认，再次发送必须填写原因。

勾选记录后点击“预览批量补发”。每批最多 50 条，按邮箱和报告去重，排除回收站、待发、发送中、已接收及结果待核实记录。预览清楚列出可发送对象与每条排除原因。填写补发原因并确认后才创建任务，部署和打开页面不会自动批量补发。

“最近批次”展示每条入队/跳过结果及最新邮件状态。处理意外中断时，继续同一批次，不创建新批次；已创建的任务通过确定性请求编号去重。每条记录的历史中保存批次编号、操作人及账号编号。

## 权限

- `nqoc-report-leads:list`：查看列表与发送历史。
- `nqoc-report-leads:send`：首次单条发送及取消待发。
- `nqoc-report-leads:resend`：再次单条发送及取消待发。
- `nqoc-report-leads:batch-send`：预览、确认及查看批量补发。

新权限不会自动授予普通角色；`all` 超级管理员可直接使用。

## 数据与一致性

- `mail`：申请记录中的原子发件箱，含当前任务编号及邮件/操作人快照。申请和自动待发状态仍由同一条写入保存，避免写一半丢任务。
- `reportdeliveries`：每次自动/人工/批量发送的独立记录，固定收件邮箱、报告版本、模板版本、触发方式、操作人、请求时间、原因；SMTP 重试逐次记录在 `attempts` 中。
- `reportdeliverybatches`：经管理员确认的批次名单、原因、操作人、创建进度与逐条结果。

新任务覆盖当前发件箱前，必须先持久化旧任务历史。创建任务后即使历史写入暂时失败，worker 仍可从发件箱中的稳定任务编号恢复。SMTP 结果先写历史，再更新申请摘要；中断后从已持久化结果修复摘要，避免重复投递。

请求编号幂等；两个 Pod 原子领取同一发件箱。单条再次操作有一分钟冷却。已知临时失败最多尝试三次，未知 SMTP 结果不自动重发。

`accepted` 仅表示邮件服务接受，不表示进入收件箱。历史页将人工发送和自动重试分别呈现，列表保留累计服务接收次数及最近接收时间，即使最近一次任务失败也不会丢掉旧成功记录。

## 历史迁移

启动时将旧的现存邮件状态快照幂等导入独立记录，并分配稳定历史编号。仅导入当时保存的信息；缺失的操作人、请求时间、版本及更早尝试不推断、不补造。迁移不会新建待发状态或向历史用户发邮件。

兼容滚动发布期间旧 worker 写回结果；终态不能回退到发送中。旧邮件继续使用原有效期内链接，新邮件链接绑定具体任务，访问时检查签名、有效期及申请是否仍有效，再跳转至限时流式 PDF 代理。

新任务链接保留报告打开追踪；旧追踪链接继续兼容两个申请来源。打开次数不等于人工阅读确认，安全扫描也可能触发访问。

## 回收站

移入回收站取消尚未开始的任务；恢复申请不会自动重发。已交给 SMTP 的消息不能保证撤回。

独立发送记录与申请共用回收站清理期限；恢复时清除其清理日期。彻底删除申请时同步清理其逐条发送记录。批次处理凭证作为操作记录保留，不代表当前仍有可下载的报告。

## 发布与回退

按 AGENTS.md 使用 digest 发布。先验证匿名发送/历史/批量接口均返回 401、静态文件匹配、两个 Pod Ready、迁移未产生非预期待发任务。

需暂停发信时，将 `REPORT_MAIL_ENABLED=false` 写入 Secret 后滚动更新。不要直接回退到没有任务下载路由的旧版本，否则新邮件中的任务链接会不可用；回退必须保留下载兼容路由及现有历史数据。

集成测试使用独立临时数据库并在结束清理，SMTP 使用模拟服务，不向真实用户发信。覆盖任务幂等、并发、重发留痕、重试日志、结果恢复、旧快照迁移、权限、回收站、任务下载链接、批量去重/排除、预览防篡改、变更复核、中断恢复。
